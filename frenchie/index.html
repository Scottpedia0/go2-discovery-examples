What We Set Up

Frenchie — on our call yesterday, Scott walked through how AI automation works at Go2: Markdown files, MCPs, skills, triggers, Agent MDs. Here is the short version of what all that means for you.

  • You have Claude Code on your Mac — it is an AI that can write code, query databases, build tools, and automate workflows
  • We pre-loaded it with access to Go2's production database — every team member's sessions, reports, worklogs, and behavioral data
  • We gave it 5 skills — data access, operational discovery, output verification, daily monitoring automations, and a support scraper
  • When you describe what you want in plain language, it figures out how to build it — you do not need to know how to code

The same skill you use to run an engagement team — knowing what needs to happen and being able to explain it clearly — is the same skill that makes this system work.

Three Rules

Before you start building anything

1
Start with your own tasks first Automate what you do every day before touching the team's workflows. Your daily work is the proving ground — if it saves you real time, then you bring it to your engagement leads.
2
Don't trust AI output without checking The verify skill uses a second AI model to catch mistakes. Use it. AI is bad at auditing its own work — the same way people are. Always run verification on anything that matters.
3
When you're stuck, just describe what you want You handle the what, Claude handles the how. If you can explain it to a new hire, you can explain it to this system.

Get Started
1 Open Claude Code on your Mac

Launch the Claude Code application. If you have not purchased the $200/month Claude Pro plan yet, that is the first thing to do — the system requires it to run.

2 Connect your apps

In Claude Code, go to Settings > Connectors. Enable Google Drive, Gmail, Calendar, and Chrome. These take 30 seconds each and give Claude direct access to your Google apps. Sign in with your go2.io Google account when prompted.

3 Paste the starter prompt

Copy the entire block below and paste it into Claude Code. You do not need to understand everything in here — the system does. Just paste it and follow along.

Hi Frenchie — I'm your Claude Code instance. Scott and Larry set me up with access to Go2's production database, your team's data, and skills to help you run discoveries, monitor your team, and automate your work. Let me run a quick check to make sure everything is connected. **Step 1: Check configuration** - Verify that ~/.claude/CLAUDE.md exists and contains Frenchie's identity - Verify that ~/.claude/skills/ contains: go2-data-access.md, operational-discovery.md, verify-output.md, engage-automations.md, daily-support-scraper.md - Report what's there and what's missing **Step 2: Test database connectivity** - Connect to the Cosmos Postgres database using the connection string in the data access skill - Run: SELECT COUNT(*) FROM go2_staff WHERE is_active = true AND division_id = 19883 - Report the result (this is how many active Engage team members are in the system) **Step 3: Test BigQuery access** - Try running: bq --project_id=cosmos-331917 query --nouse_legacy_sql --format=csv "SELECT COUNT(*) as total FROM cosmos-331917.go2_data_warehouse.rpt_agent_bi_session WHERE DATE(start_time) = DATE_SUB(CURRENT_DATE(), INTERVAL 1 DAY)" - If this works, report how many sessions were recorded yesterday - If this fails, that's okay. Just tell me: "BigQuery isn't set up yet — that's a quick one-time setup Scott can help with. Everything else works." **Step 4: Report results and offer options** After running those checks, tell me what worked and what didn't. Be honest — some things might need debugging and that's normal. Then ask what I want to do: a. **Show me my team's status right now** — Pull today's SOD/EOD reports and session data for the Engage division (19883). Show who's filed reports today, who hasn't, and any flags. This works with just the Cosmos database. b. **Run a discovery on one of my client accounts** — I'll tell you which client, and you'll run the full operational discovery pipeline to produce a report and tools. c. **Set up my daily monitoring automations** — Configure the session breathing monitor (weekday mornings) and the remission/decline monitor (daily at 11pm PHT) to run automatically and send summaries on Slack. d. **Help me with something else** — I'll describe what I need and you figure out how to do it. Whenever you want to come back to these options, just say "menu." And if you ever get stuck, just describe what you want in plain language — I'll figure out how to build it.
4 Pick what you want to do first

After the system checks pass, it will give you four options. Start wherever feels most useful. Most people start with option A — seeing their team's current status — because it gives you something real to look at immediately.

5 Try things. Break things. Ask questions.

There is no way to break the production data — your access is read-only on the database side. Experiment freely. If something does not work, describe what happened in the Slack thread and either Larry or Scott will sort it out.

Some of this will need debugging — that's normal. The BigQuery connection might need setup, and some automations will take a few tries to get right. But as long as the Gmail connector works, the system automatically sends Scott a daily report of anything that broke. You don't have to remember to ask for help — it surfaces your problems automatically.
